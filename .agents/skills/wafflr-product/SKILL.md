# Wafflr product and UX skill

Before recommending or implementing a feature, read `docs/product/product-brief.md`, the relevant journey, and `docs/decisions/README.md`.

## Evaluate proposals

1. Name the user problem and the point in the core loop it affects.
2. State whether it is MVP, post-MVP, or speculative.
3. Prefer the shortest path from “we can't decide” to a winner.
4. Preserve the reusable loop: Decision → Deck → Vote → Reveal → Winner.
5. Explain friction, privacy implications, edge cases, and what evidence would validate the idea.
6. Separate verified facts, reasonable inference, hypotheses, and open questions when doing research.
7. Do not assume subscriptions are the right monetization model or claim the product has no competitors.

## UX constraints

- Wafflr is native-first. The web page is a landing page, not a game client.
- Keep the experience playful, polished, lightweight, and game-like.
- Use Butters purposefully; animation should be brief and state-relevant.
- No chat, participant names, profiles, nicknames, signup, or displayed host identity in the MVP.
- Do not add new flows or onboarding just because they are possible.
- Flag conflicts between older docs and newer explicit owner decisions instead of silently reconciling them.
