# Wafflr asset inventory

Status values: **Required** means the UI needs an asset of this role; **Reuse candidate** means audit existing files before creating another; **Optional** means not needed for the first playable MVP. Exact pixel dimensions are provisional until the target rendering size and existing asset files are inspected.

## Rules to reduce redundancy

- One shared UI asset should serve every screen where possible; do not generate a new button, pill, panel, or background for each screen.
- Dynamic labels, titles, codes, card names, counts, and status text must remain native text.
- Prefer a small number of scalable/reusable branded assets over many near-identical variants.
- Keep white-background source exports only where required by the asset workflow. Confirm whether the runtime needs the white background or whether a clean cutout is required before producing final exports.
- Do not create separate art for states that can be represented by a reusable component plus a tint/state change.
- Keep source files, runtime exports, and inventory entries linked.

## Explicitly do not generate yet

- A separate background image for every screen.
- Separate primary/secondary buttons for every label or screen.
- Image files containing dynamic text such as “Create Room,” room codes, card names, guest counts, or vote totals.
- Separate card frames for restaurant/movie/activity/custom templates unless user testing demonstrates that the frame must change.
- A complete six-to-eight-frame animation set for every character before the static MVP flow is validated.
- Multiple near-identical Butters idle poses.
- A full set of app-specific modal illustrations when one reusable character pose works.

## Audit checklist for existing assets

For every existing file, record its actual filename, dimensions, format, background/alpha behavior, padding/safe area, variant, source/editable file, current consumers, and whether another file duplicates its role. Mark each file **keep**, **replace**, **merge**, or **retire**. Do not create replacements until this audit is complete.

## Important limitation

The current GitHub repository does not yet contain the user's existing artwork library in the tracked asset tree. Therefore this is a proposed target inventory, not a verified list of files already owned or files that must definitely be generated. Reconcile this list against the actual files before commissioning or generating assets.
